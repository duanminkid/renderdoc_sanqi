# 数据库代码规范

## 迁移
- 每次 Schema 变更对应一个迁移文件
- 迁移可逆（有 up 和 down）
- 不在迁移中写业务逻辑
- 测试环境运行完整迁移后再测试

## 查询性能
- 避免 N+1 查询问题
- 使用适当的索引
- 复杂查询用 EXPLAIN 分析
- 大批量操作用批处理

## 连接管理
- 连接池大小合理配置
- 连接使用后及时释放
- 事务尽量短小
- 不在事务中做外部 I/O（发邮件、调 API）

## 数据完整性
- 关键字段有约束（NOT NULL、UNIQUE、FOREIGN KEY）
- 使用数据库级别的约束而非仅应用层校验
- 软删除优先于硬删除（业务数据）
